# Git and GitHub

Git and GitHub visualization remain in scope because Markdown and code review workflows depend on repository context.

Supported expectations:

- View changed files in a repository.
- Inspect diffs while editing Markdown or code.
- Review changes to agent instruction files, plans, and documentation.
- Use GitHub-related views where they support understanding repository changes.

Non-goals:

- Replacing a full Git terminal workflow.
- Reintroducing collaboration or cloud accounts as a dependency.
- Expanding into a general project-management client.

Keep Git and GitHub features focused on local context and review-oriented visualization.
