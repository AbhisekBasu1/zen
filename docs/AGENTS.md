# Zen docs guidelines

Document Zen as a calm, repo-native Markdown workspace for humans and AI agents, not as a general-purpose IDE.

## Scope

Cover these workflows:

- Reading and editing Markdown.
- Markdown preview.
- Agent instruction files such as `AGENTS.md`, `CLAUDE.md`, and `.github/copilot-instructions.md`.
- Planning docs, specs, runbooks, changelogs, and repository docs.
- File and project search.
- Lightweight code reading and editing.
- Git and GitHub visualization.

Do not document removed Zed product areas unless they are explicitly reintroduced:

- Built-in AI assistants.
- Collaboration.
- Remote development.
- Extensions marketplace.
- Terminal workflows.
- Debugger workflows.
- Accounts, telemetry, or cloud services.

## Style

- Be practical and direct.
- Describe current behavior, not aspirational features.
- Call the app Zen in user-facing docs.
- Present Markdown as repository infrastructure and agent context, not just prose documentation.
- Use the calm/focused Zen identity without becoming vague or mystical.
- Mention the Zed fork only when origin, licensing, or internal implementation context matters.
